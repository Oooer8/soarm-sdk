Install

Install the package in editable mode from the repository root.

pip install -e .

This workspace uses the soarm-sdk conda environment for local validation.

conda run -n soarm-sdk python -m pip install -e .
conda run -n soarm-sdk python -m soarm.cli status --config configs/soarm.yaml --mock
Mock mode is useful for CLI, Web, and documentation checks. It does not replace real checks for wiring, servo IDs, voltage, torque behavior, or mechanical range.

Hardware

The current target is a SOARM / SO-ARM101 style arm using Feetech STS3215 servos at 1 Mbps. The SDK talks to the bus through soarm.hardware.ServoBus, backed by scservo_sdk.

Servo IDs must already match the YAML configuration. The SDK does not infer joint order from the bus. If several new servos share the factory default ID, connect and rename one servo at a time with vendor or low-level Feetech tooling.

Configuration

configs/soarm.yaml is the shared entry point for CLI, Web, and Python API usage.

includes:
  runtime: runtime.yaml
  motor_profile: motors/feetech_sts3215.yaml

configs/soarm.yaml

Arm name, serial port, baud rate, joint IDs, calibration, soft limits, and named poses.

configs/runtime.yaml

Control frequency, feedback frequency, Web sync/render rates, voltage threshold, and max step.

configs/motors/feetech_sts3215.yaml

Feetech register policy: PID, return delay, acceleration, mode, and gripper protection.

Joint limits

max_vel_rad_s and max_acc_rad_s2 are joint-space safety and planning limits, not direct per-move Feetech register values.

First Bring-Up

  1. Inspect wiring, power, linkage travel, and gripper clearance with power off.
  2. Assign servo IDs to match configs/soarm.yaml.
  3. Install the SDK and run the mock status command.
  4. Scan and save the serial port.
  5. Run real status and inspect communication, voltage, raw position, and soft-limit results.
  6. If calibration is missing or stale, run calibration.
  7. Save calibration and immediately run post-calibration status.
  8. Check the Feetech motor profile.
  9. Try a small low-speed move or named pose.
  10. Open the Web GUI for visual feedback and slider control.
conda run -n soarm-sdk python -m soarm.cli ports --config configs/soarm.yaml
conda run -n soarm-sdk python -m soarm.cli status --config configs/soarm.yaml
conda run -n soarm-sdk python -m soarm.cli calibrate --config configs/soarm.yaml --output configs/soarm.yaml
conda run -n soarm-sdk python -m soarm.cli configure-motors --config configs/soarm.yaml --check-only
conda run -n soarm-sdk python -m soarm.cli home --config configs/soarm.yaml --duration 2.0

CLI Reference

Port discovery

soarm ports --config configs/soarm.yaml
soarm ports --config configs/soarm.yaml --port /dev/cu.usbmodem5A7C1190351
soarm ports --config configs/soarm.yaml --no-update

Health and calibration

soarm status --config configs/soarm.yaml
soarm calibrate --config configs/soarm.yaml --output configs/soarm.yaml

Joint reads and motion

soarm read --config configs/soarm.yaml --unit rad
soarm home --config configs/soarm.yaml --duration 1.5
soarm move --config configs/soarm.yaml shoulder_pan=0.0 elbow_flex=0.5 --duration 1.0
soarm pose --config configs/soarm.yaml ready --duration 1.0

Maintenance and debugging

soarm configure-motors --config configs/soarm.yaml --check-only
soarm configure-motors --config configs/soarm.yaml
soarm configure-motors --config configs/soarm.yaml --force
soarm probe-joint shoulder_pan --config configs/soarm.yaml --delta -0.1 --duration 1
soarm capture-pose --config configs/soarm.yaml ready --output configs/soarm.yaml
soarm disable --config configs/soarm.yaml

Kinematics

soarm fk --config configs/soarm.yaml shoulder_lift=-0.3 elbow_flex=0.5
soarm ik --config configs/soarm.yaml 0.42 0.0 0.20

Web GUI

Start the local browser console:

conda run -n soarm-sdk python -m soarm.cli web --config configs/soarm.yaml --mock

Without --mock, the Web server talks to the configured serial bus. The default URL is http://127.0.0.1:8765/.

PhasePurpose
DetectSelect port, save arm name/port, edit runtime frequencies, and run status.
CalibrateDisable torque, capture zero, sweep all joints, review new limits, and save calibration.
Visualize/controlLoad URDF, stream real joint feedback, enable torque, and send slider targets through SDK safety checks.
The Web GUI only enters control when a calibration exists, current status passes, and current joint positions are inside saved soft limits.

Teaching Record And Replay

Record joint-space demonstrations as JSON:

soarm record-demo demos/pick_place.json --config configs/soarm.yaml --duration 10 --hz 20
soarm record-demo demos/elbow_only.json --config configs/soarm.yaml --joints shoulder_pan elbow_flex

Validate and replay safely:

soarm replay-demo demos/pick_place.json --config configs/soarm.yaml --dry-run
soarm replay-demo demos/pick_place.json --config configs/soarm.yaml --speed 0.5
soarm replay-demo demos/pick_place.json --config configs/soarm.yaml --output-hz 200 --interpolation pchip

The demonstration format is soarm.demonstration.v1. It stores created_at, metadata, selected joints, and time-stamped radian samples. Replay validates the file, moves through a safety-checked lead-in, interpolates sparse samples to setpoints, and reuses SDK limit checks.

Python API

from soarm import SOARM

with SOARM.from_config("configs/soarm.yaml") as arm:
    arm.enable()
    arm.move_home(duration=1.5)
    arm.move_joints(
        {
            "shoulder_pan": 0.0,
            "shoulder_lift": -0.4,
            "elbow_flex": 0.8,
        },
        duration=2.0,
    )
    print(arm.get_joint_positions())

Demonstration helpers

from soarm import SOARM, record_demonstration, replay_demonstration

with SOARM.from_config("configs/soarm.yaml") as arm:
    record_demonstration(arm, "demos/pick_place.json", duration=10, sample_hz=20)

with SOARM.from_config("configs/soarm.yaml") as arm:
    replay_demonstration(arm, "demos/pick_place.json", speed=1.0)

Safety Gates

Use status as the read-only gate before real motion. It checks:

  • configured servo IDs are online
  • current positions can be read
  • current positions are inside soft limits
  • voltage is above the configured threshold

Calibration readiness is different from control readiness. Old soft limits may fail while communication, voltage, and raw position reads are still healthy enough to recalibrate. Control requires a saved calibration and a passing current status.

LayerDefaultPurpose
Trajectory input60 HzHigh-level targets from policy, user input, or planner.
Controller interpolation200 HzConvert targets into regular setpoints.
Feedback sampling100 HzRead and cache real joint state.
Web state sync30 HzSend cached state to the browser.
Web rendering60 HzUpdate the visualization.

Troubleshooting

SymptomLikely causeNext step
Status fails on communication Wrong serial port, baud rate, cabling, power, or servo ID. Run soarm ports --config configs/soarm.yaml --no-update, then verify wiring and IDs.
Status fails only on soft limits The arm is outside saved limits or calibration is stale. Move the arm back into range and rerun status, or recalibrate.
Goal_Position changes but servo does not move Torque, operating mode, motor profile, current/load, or command block issue. Run probe-joint and inspect Torque_Enable, Operating_Mode, Moving, Acceleration, and Goal_Velocity.
Replay lead-in reports a large remaining delta The joint is not following position commands or present-position readback is stale. Probe the failing joint and slow lead-in with --lead-in-duration.
Voltage fails Power supply is below threshold or unstable. Do not move until power is corrected, then rerun status.
Joint direction or zero looks wrong Bad zero capture, direction inference, or sweep range. Stop motion, recalibrate, and verify zero ticks and radian limits before enabling torque.

Architecture

CLI and Web are thin adapters. Shared SDK layers own hardware rules, calibration math, safety, kinematics, and config writes.

Applicationssoarm.cli, soarm.web, soarm.webapp, examples, scripts
SDK facadesoarm.arm.SOARM exposes the user-facing Python API.
Shared workflowsworkflows, diagnostics, calibration, kinematics, demonstration
Motion and safetymotion and safety check limits, voltage, step size, and trajectory feasibility.
Hardware busServoBus owns register I/O only: sync read, sync write, torque, modes, PID, and profile helpers.
Keep high-level planning out of ServoBus. Motion planning, retargeting, and safety policy should stay in the motion and SDK layers.

Development And Validation

Use mock checks before touching hardware:

conda run -n soarm-sdk python -m soarm.cli status --config configs/soarm.yaml --mock
conda run -n soarm-sdk python -m soarm.cli fk --config configs/soarm.yaml shoulder_lift=-0.3 elbow_flex=0.5
conda run -n soarm-sdk python -m soarm.cli ik --config configs/soarm.yaml 0.42 0.0 0.20
conda run -n soarm-sdk python -m soarm.cli record-demo /tmp/soarm-demo.json --config configs/soarm.yaml --mock --duration 1
conda run -n soarm-sdk python -m soarm.cli replay-demo /tmp/soarm-demo.json --config configs/soarm.yaml --dry-run

When changing code, keep these boundaries intact:

  • ServoBus owns register I/O only.
  • SOARM exposes the public SDK facade.
  • Motion planning and safety live outside the hardware bus layer.
  • CLI and Web call shared workflow/API code instead of duplicating calibration math, safety gates, FK/IK, or config writes.
